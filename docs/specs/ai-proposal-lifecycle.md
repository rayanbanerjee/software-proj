# AI Proposal Lifecycle

## Purpose

Define the first end-to-end local AI request flow so the API, worker mocks, and web shell can share a stable lifecycle before real provider orchestration or persistence is introduced.

## Request Flow

1. The web client submits `POST /v1/documents/:documentId/ai/requests`.
2. The payload includes:
   - `action`
   - optional `prompt`
   - `context.scope`
   - `context.selectedText`
   - `context.surroundingText`
   - `maskPersonalData`
3. The API validates document access and request shape.
4. The API sends the request through a local mock-provider path for development.
5. The API stores the resulting request status and proposal in memory for later polling.

## Status Model

- `queued`: accepted but not started yet
- `running`: provider work in progress
- `succeeded`: proposal available for review
- `failed`: provider or validation failure
- `cancelled`: proposal explicitly rejected
- `stale`: proposal no longer valid against current document context

## Proposal Model

Each successful request yields one proposal with:

- `proposalId`
- `requestId`
- `documentId`
- `action`
- `originalText`
- `proposedText`
- `summary`
- `createdAt`
- `isStale`

## Decision Flow

- `POST /v1/documents/:documentId/ai/proposals/accept`
  - validates the proposal exists and is not stale
  - returns `appliedAt`
- `POST /v1/documents/:documentId/ai/proposals/reject`
  - marks the request lifecycle as cancelled
  - clears the active proposal from status polling
  - returns `rejectedAt`

## Web Expectations

- the AI panel must represent:
  - idle state with available actions
  - in-flight generation state
  - proposal-ready review state
  - failed, cancelled, or stale retry state

## Current Limits

- proposals are generated by a local mock provider
- request and proposal state are stored in memory only
- accept does not yet mutate the editor document
- stale detection is not yet implemented beyond the explicit boolean field

## Follow-Up

- move request execution to the worker queue
- replace in-memory records with durable `AiRequest` persistence
- implement stale detection against revision and selection state
- apply accepted proposals through the normal editor or collab mutation path
